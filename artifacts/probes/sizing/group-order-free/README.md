# Exact group acquisition without a known order

The learner can now recover a finite group action from equality of positive words without receiving the group order. On six fresh marked S₅ actions, a checked proposal reduced paid calls from 8,186 to 110. On the other 12 cases, the proposal path rejected and the same fallback recovered the exact action. This is a fixed-panel result for an S₅ proof library.

## Frontier closure

Start with the empty word. Process both outgoing edges of each representative in breadth-first order. A generator acts bijectively, so a target already used by an earlier source in the same column cannot match the new edge. Test the remaining representatives, reusing exact answers when two comparisons reduce to the same pair by group cancellation. Add a new representative only after excluding all eligible known states.

Every committed representative denotes a distinct element. All elements found by completing the frontier have committed transitions under both generators. The resulting set contains the identity and is closed under generation, so it contains the entire positive orbit. In a finite group that orbit is the group generated by the marks. With N elements, the learner processes at most N rows. At the j-th row, counted from zero, each generator has j committed targets, so there are at most N − j candidate comparisons. Summing over both columns gives at most N(N + 1) calls before cache savings.

The implementation passes `None` as the size to the existing acquisition code. The no-size mode traverses until closure and never uses the size-based forced merge. The tested route uses only the equality oracle, the known two generator names, and group cancellation.

## Preregistered comparison

Both arms started with the same access to the hidden oracle. The proposal arm first selected one of 57 marked S₅ actions. It verified the transported Coxeter equations and the noncommutation check from the [compact certificate experiment](../group-certificate/README.md). It reused identical selection answers during verification. On rejection it ran the original no-size learner from scratch. A fixed 150,000-call harness cap was applied to each arm. All 36 runs completed within it.

The primary gate required at least 95% savings in both calls and symbols on fresh S₅ and at most 24 extra calls per outside case. Savings were 98.66% in calls and 98.02% in symbols. The proposal arm spent 35 selection calls and 75 certificate calls across the S₅ cases. On outside cases it spent at most 16 extra calls in any one case. The trivial marking and all three generating C₂ markings were deliberately reused quotient controls. Three reached the noncommutation check and failed it. The remaining 14 cases were previously unseen canonical actions.

The independent auditor checked the complete comparison tapes, 9,052 transition entries and 3,456 held-out words. It rejected a truncated frontier, a flipped paid answer, and a forged kernel check. On macOS the cached proof library took 0.038 s to load and check. The frontier and proposal-first paths took 0.307 s and 0.417 s respectively across the panel after setup, with the oracle implemented as an in-process table walk. The experiment measured query cost without emulating remote or human response latency.

## Bounding the cost of a bad proposal

The trivial control exposed the cost of always proposing first. We replayed a schedule on the same audited tapes that allows one speculative call per four calls paid by the frontier. The two paths share identical unordered answers. The schedule stops when either path recovers the action and drops the speculative path after rejection.

If the isolated frontier would use B calls, the combined run makes at most B + floor(B/4) calls. Its cache preserves the frontier's answers and can only reduce its paid count. If the isolated proposal would certify in P calls, it needs at most four frontier-paid calls to fund each speculative one, so the combined run uses at most 5P. These bounds concern call count. They place no bound on input symbols per call.

The counterfactual used 540 calls on the six S₅ cases, retaining 93.40% savings versus frontier-only. It matched the frontier's two calls on the trivial group and used 12 calls versus 11 across the three C₂ controls. The checker also exercised the accounting bound on 213,576 synthetic tape pairs and outcomes. This test uses existing responses to deterministic paths. An implementation that pauses and resumes both learners against a live oracle remains a separate experiment.
